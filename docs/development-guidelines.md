# 开发指导文档

## 项目测试策略

本项目采用手动测试和代码审查的方式，不包含前端单元测试和集成测试文件。

### 为什么不使用前端测试文件

1. **项目特性**: 本项目是一个计算器应用，主要逻辑集中在数据计算和用户界面展示
2. **维护成本**: 前端测试文件需要持续维护，与快速迭代的需求不匹配
3. **测试覆盖**: 核心计算逻辑在Go后端，前端主要负责数据展示和用户交互
4. **开发效率**: 专注于功能开发和用户体验优化，而非测试维护

### 推荐的测试方法

1. **手动测试**: 开发者手动验证功能正确性
2. **代码审查**: 通过代码审查确保代码质量
3. **用户体验测试**: 实际使用场景下的功能验证
4. **性能监控**: 使用浏览器开发者工具监控性能

### 如需添加测试的情况

以下情况可以考虑添加测试文件：
- 复杂的业务逻辑计算
- 关键的数据转换处理
- 第三方API集成
- 多浏览器兼容性要求

请开发者在添加测试文件前先评估其必要性和维护成本。
